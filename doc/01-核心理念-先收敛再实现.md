# 核心理念:先收敛,再实现

> 这是整套方法论的地基。如果你只带走一条思想去下一个项目,就是这一条:**不要从一句模糊的诉求直接冲向成品,而是先把"想清楚"和"做出来"拆开,让意图沿着一条漏斗逐级收窄;并且把每一级的收敛结果外化成一份能被人独立打开、阅读、修改的持久产物,而不是让它留在一次性的对话或运行时内存里。**
>
> 本篇只讲两件事:**为什么要先收敛(漏斗式管线)**,以及**为什么要工件驱动(把每一步沉淀成产物),它换来了什么**。至于"阶段之间如何约束迁移、如何设门",属于《流程编排》那一篇;"每份产物内部如何建模任务"属于《需求与任务建模》那一篇;"如何真正验证产物是对的"属于《验证闭环》那一篇——本篇一律不展开,只在需要衔接时点到为止。

---

## 一、先收敛,后落地:在意图与实现之间架一条漏斗

**是什么。** 在"模糊诉求"与"最终实现"之间,插入一串逐级具体化的中间交付物。每一级只负责把范围收窄一点点,且必须消费上一级的产物、产出自己的产物;流程上**禁止越级从起点直达终点**。典型的收敛台阶是:澄清意图 → 形成规格 → 形成计划 → 拆成工作项 → 执行 → 审查。前半段(意图到计划)只做"收窄决策",一行实现都不写。

**为什么有价值。** 直接从一句话跳到成品,几乎必然带来范围漂移、拆解混乱、过程不可追踪——而且错误被发现得越晚,返工越贵。把"从意图到实现"拆成有序的收敛台阶,等于把纠错点前移到最便宜的早期:范围与契约在还只是几行文字时就被锁定,每一步的返工成本都被关在本级之内,不会顺着下游滚雪球。

**怎么应用到新项目。** 为你的交付定义一条**固定的、有序的**阶段链;约定每一级的输入就是上一级的输出,每一级都必须产出一个能被独立评审的东西。把"从哪里到哪里"设计成单向漏斗——越往后,范围越窄、承诺越硬、改动越贵。在最前面的收敛阶段,强迫自己把"没想清楚的地方"显式暴露出来:用一份固定骨架把原始诉求映射成若干槽位(目标、背景、硬约束、纳入范围、默认假设、待确认问题、成功信号、风险),**填不出来的槽位本身就是信号**。信息不足时,只允许新增"假设"和"待确认问题",**绝不允许生成方自己扩展范围去填空**——这是范围收敛真正的闸门。同样,规格里既要写"要做什么",也要专门写"明确不做什么",把排除项写得和纳入项一样具体。

**常见坑 / 反模式。**
- **漏斗退化成仪式。** 如果早期阶段只是套模板生成一堆通用套话,它并没有真正收敛任何决策,却增加了成本。要保证每一级产物都是"承载决策的",而不是充数的空壳——一份没有锁定任何范围、没有排除任何诱惑的规格,不如没有。
- **收敛骨架被写死在某个领域。** 固定维度这张"体检表"必须保持领域无关;领域知识应作为可替换的输入喂进去,而不是硬编码进骨架,否则换个领域就退化成空壳。
- **排除项写成万能套话。** "不做无关优化""不引入新基础设施"如果不结合本次的具体诱惑点,就失去约束力,后续挡不住任何一次范围蔓延。
- **假设无人回收。** 显式假设若没有一条回流机制把"待确认问题"送回决策,就会沉淀成隐性事实,假设列表只是免责声明。

## 二、工件驱动:把每一步外化成持久、可审阅的产物

**是什么。** 每个阶段的结果都写成一份独立、人类可读、可编辑、且能**脱离当次会话长期存在**的产物,而不是只留在一次性的工作记忆或对话上下文里。真理源是这些被持久化下来的产物,不是某个会话实例。

**为什么有价值。** 对话在关掉窗口的一刻就消失了,别人无法接手,你自己第二天也接不上。而持久产物可以被审改、被随时回放、被不同角色在不同阶段接力、被版本化和比对。这是"从意图到实现全程可追踪"的**物理基础**——没有它,后面要讲的四种能力(可审改、可回放、可交接、可续作)全都无从谈起。

**怎么应用到新项目。** 为每一阶段指定一个持久化的产物落点;产物形态要让人能直接打开阅读和修改;并把这些产物本身当作下一级读取的"事实来源",而不是把中间结论藏在运行时内存里。理想形态是**产物即接口**:同一份东西既是人类可读可手改的文档,又是机器可解析的数据,人在它上面评审、修改,系统再解析回去,形成闭环,消除人机之间的翻译损耗。

**常见坑 / 反模式。**
- **往返有损。** 这是工件驱动最隐蔽的杀手:产物写出时携带了丰富信息,解析读回时却只认其中一部分、其余静默丢弃。于是评审者手改的关键信息被悄悄吞掉,他以为改生效了,其实没有。**凡是声称"可往返/可编辑"的产物,读路径必须与写路径逐项对齐,并用往返测试(写出再读回应等价于原件)守护**,否则不要对外承诺"可编辑"。
- **关键元信息只活在内存里。** 产物看起来很权威,但"它是怎么生成的、可信度如何"如果没有和产物一起持久化,就等于隐藏了它的出身(参见《健壮性与可演进设计》)。
- **把"持久化"误当成"支持协作"。** 持久化支撑的是**错时接力**(我停下,你接着走),不等于支持并发协作。若多个角色或"自动推进 + 人工修改"同时动同一批产物,而底层没有任何协调,竞争会悄悄毁掉数据。要么明确"同一时刻只能有一个人推进",要么另配真正的协调机制——别假装文件级读写就能支撑多人同时动手。

## 三、工件驱动换来的四种能力

先收敛给了你**正确的顺序**,工件驱动给了你**可操作的介质**。二者叠加,自然长出下面四种能力。它们不是额外功能,而是"把每一步外化成产物"的直接推论。

### 3.1 可审改:机器只提议,人来定夺

**是什么 / 为什么。** 每份生成的产物都只是**可覆盖的草稿**,人可以直接就地编辑,编辑后的版本就是下游读取的真理源。把最终权威留在人手里,避免"自动产物不可纠正"的陷阱。

**怎么应用。** 为每份产物提供编辑入口,保存即写回下游读取的同一处;下游永远消费"人最新确认过的版本",而不是某次生成的快照。更进一步,**覆盖前先快照**:替换一份产物前归档旧版,允许恢复到任一历史版本,而且回滚前把"当前版本"也快照一份,让回滚本身也可逆。每次变更都可逆、都留痕,人才敢放心大胆地编辑和重生成。

**常见坑。**
- **重新生成静默覆盖手工修改。** 这会让信任瞬间崩塌。"重建/覆盖"必须藏在一个显式开关后面——默认应当**拒绝**在已有人工产物之上重建,除非明确要求覆盖。
- **回滚变成任意读取的口子。** "恢复到历史版本"必须限定在版本库范围内,对选中的目标做边界校验,否则"回滚"会退化成读取任意内容的后门。

### 3.2 可回放 / 可交接:留一条时间轴,让别人接得住半成品

**是什么 / 为什么。** 除了产物本身,每一次改变状态的动作都写一条带时间戳的记录,形成一条**只增不改的事件轨**。它回答的是"随时间发生了什么"——生成、编辑、批准、回滚、执行、配置变更都各记一条。任何角色拿到这条时间轴,都能重建"发生过什么、何时发生",这是审计与接手半成品的支柱。

**怎么应用。** 抽一个集中的事件记录器,所有关键动作统一经它记一条;提供一个"最近发生了什么"的视图。让事件轨在存储层**真正做到只增不改**——不是"每次把整份历史读出来、追加、再整体写回"(那既不崩溃安全也不可扩展,只是长得像追加)。

**常见坑。**
- **只记"做了什么",不记"谁做的"。** 如果预期在人与人之间交接,动作的发起者必须一并记录,否则多角色问责无从谈起,时间轴只能告诉你"发生了",不能告诉你"谁干的"。

### 3.3 可续作:从持久状态推导下一步,而不是重放整段过程

**是什么 / 为什么。** 因为进度和产物都被持久化了,流程可以在任意点停下、之后从冷态重新进入:每一轮只读取持久状态、判断"下一个尚缺的步骤是什么"、做且只做那一步,完全不依赖内存里的会话上下文。跑到一半停了,重新点一下就从当前状态接着走。这让流程天然幂等、可中断、可重跑、可交接。

**怎么应用。** 把"当前进行到哪一步"表达成显式的、被持久化的状态;每个步骤先检查"是否已完成",是则跳过、否则执行;整个推进逻辑只从持久状态出发,不从会话记忆出发。

**边界与坑(点到为止)。**
- **本篇不展开状态机本身。** "有哪些合法阶段、如何校验迁移、如何防止非法跳跃与倒退、如何设门"属于《流程编排》。这里只强调一点:**续作依赖"进度被持久化成显式状态"这个物理前提**,而"只记录了阶段标签"和"真正约束了阶段迁移"是两回事——前者只是进度便签,不是状态机。
- **检查点建好了却没有消费端。** 一个真实教训:如果你把整轮推进塞进一次会阻塞到底的调用里,虽然过程中不断写检查点,但在这次调用返回前没有任何消费者去读它——使用者还是要等全部跑完才看得到进度。**可续作 / 实时进度的价值,只有接上一个真正的实时消费端(主动查询或持续推送)才兑现**,基础设施建好不等于价值交付。

## 四、给工件标注来源(点到为止)

每份产物还应标注它的出身——是高投入的主生成路径,还是降级后的兜底,以及降级的原因——好让下游据此校准信任。这里只强调一条与本篇直接相关的物理前提:**来源信息必须与产物一起持久化**;只活在运行时内存里、进程一退就蒸发的标记,等于没有提供可追溯性——因为一个高投入的结果和一个"失败后凑出来的兜底结果"外观可能一模一样,来源是区分二者、也是诚实交接的唯一线索。至于降级策略本身、来源标记的完整设计与在各入口的展示,参见《健壮性与可演进设计》。

## 五、如何应用到你的下一个项目(要点清单)

1. **架一条单向漏斗。** 在"意图"和"实现"之间定义一条固定、有序的收敛链,前半段只收窄决策、不写实现;流程上禁止越级直达终点。
2. **每一级都要承载决策。** 用"能不能独立评审、锁定了什么范围、排除了什么诱惑"来检验每份产物;凡是套话空壳,一律视为漏斗退化的信号。
3. **用固定骨架承接模糊意图。** 目标、约束、纳入范围、默认假设、待确认问题、成功信号……填不出来的槽位就是风险点;信息不足时只准加假设和问题,不准偷偷扩范围。
4. **把每一步外化成持久、人类可读、可编辑的产物。** 让产物成为下游的唯一事实源,别把中间结论留在对话或内存里。
5. **对"可往返"零容忍地较真。** 声称可编辑的产物,读路径必须与写路径逐项对齐,并用往返测试守护,否则不要承诺可编辑。
6. **机器产出一律当草稿。** 提供就地编辑;重生成默认不覆盖人工修改,覆盖必须显式;替换前快照、回滚可逆、回滚范围受限。
7. **留一条只增不改的事件轨,并记下"谁在何时做了什么"。** 它是回放、审计、接手半成品的支柱。
8. **让进度成为显式的持久状态,推进只从状态出发。** 保证可中断、可重跑、可续作;若要实时进度,记得接上真正的消费端。
9. **给每份产物打上来源标记,并和产物一起持久化。** 只活在内存里的标记等于没有可追溯性;完整的来源与降级设计参见《健壮性与可演进设计》。
10. **警惕"看起来跑通了"。** 漏斗、产物、留痕都是为了让错误在最便宜的地方暴露;别让流程的顺畅感替代"这一步真的收敛了吗"的判断——本篇管收敛与产物,产物"是不是对的"交给《验证闭环》那一篇。
